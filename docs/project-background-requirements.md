# 项目转型方向：面向秋招简历的 ShopGuide Agent

本文档原本用于记录课程课题背景和验收要求。课程已经结束后，项目目标调整为：把 ShopGuide Agent 打造成一个适合投递前端、全栈和 Agent 开发岗位的个人项目。

## 1. 新定位

ShopGuide Agent 是一个基于 RAG 的电商智能导购 Agent。它的核心价值不是“套壳聊天”，而是把用户的自然语言购物需求转成可验证的商品检索、推荐、对比和决策辅助流程。

新的项目主线：

```text
Web 前端交互
-> Node.js 后端 Agent 编排
-> 商品数据加载与检索
-> 意图解析、多轮记忆、过滤和排序
-> LLM 或本地规则生成
-> SSE 流式返回
-> 商品卡片、对比卡、追问卡片和调试面板展示
```

Android 客户端作为历史实现保留，但不再是主展示端。后续开发优先建设 Web 客户端，让项目更适合前端/全栈岗位展示。

## 2. 面向岗位的展示重点

### 2.1 前端岗位

- 使用 React 或 Vue 构建主客户端，展示现代前端工程能力。
- 实现 SSE 流式渲染、消息队列、局部 loading、错误重试、断线恢复等真实交互问题。
- 设计商品卡片、对比卡、追问卡片、详情抽屉、检索调试面板等复杂组件。
- 体现状态管理能力：会话列表、当前对话、流式中间态、商品卡片集合、购物车或收藏状态。
- 体现体验打磨：响应式布局、骨架屏、空状态、错误态、快捷筛选、键盘交互和可访问性。

### 2.2 全栈岗位

- 前端与后端通过清晰的 API/SSE 协议协作。
- 后端提供健康检查、商品列表、商品详情、检索调试、性能统计和聊天流式接口。
- 保留测试与评测脚本，用于说明核心链路可回归、可量化。
- 可以进一步加入 Docker Compose、部署脚本、环境变量示例和 README 一键启动说明。

### 2.3 Agent 开发岗位

- 突出 RAG 链路：意图解析、检索、过滤、排序、Prompt 构造、模型生成和结构化事件返回。
- 突出防幻觉边界：商品事实必须来自数据集，模型只负责表达和推理。
- 突出多轮能力：预算继承、反选约束、商品指代、跨需求恢复、对比决策。
- 突出可解释性：通过 debug/review 面板展示本轮检索 query、过滤原因、候选商品和排序证据。

## 3. 技术路线建议

建议采用“先 Web 化，再增强 Agent 体验”的路线。

### 阶段一：Web 主客户端

- 新增 `web/` 目录。
- 使用 React + TypeScript + Vite 或 Vue + TypeScript + Vite。
- 接入现有后端 `/api/chat` SSE。
- 复刻当前 Android 的核心体验：聊天窗口、流式回答、商品卡片、详情页、对比卡。
- 建立基础前端工程脚本：`dev`、`build`、`lint`、`test`。

### 阶段二：简历亮点组件

- 追问卡片：当需求过宽泛时，让 Agent 返回结构化问题和选项。
- 检索可解释面板：展示意图、过滤、排序和候选商品证据。
- 商品对比工作台：把多商品对比从纯文本升级为结构化表格和结论卡。
- 商品详情抽屉：展示图片、价格、属性、推荐理由、FAQ 和用户评价。

### 阶段三：全栈与 Agent 加分

- 热门查询缓存、首 token 延迟统计、错误降级提示。
- 购物车或收藏能力，优先做 Web 端状态和本地持久化。
- 接入真实向量数据库 Qdrant，并保留 local 模式作为无外部依赖兜底。
- 为追问、指代、反选、对比、卡片一致性补充自动化测试。

## 4. 保留的核心原则

- 商品事实以数据集为准，不能编造商品、价格、库存、优惠或功能。
- SSE 结构化事件是前后端契约，前端不要从模型自然语言里反向解析商品事实。
- 后端负责可信边界、检索、过滤和结构化商品集合控制；模型负责语言表达和解释。
- 项目文档应面向招聘展示：说明问题背景、技术方案、工程难点、关键取舍和效果验证。

## 5. 不再适用的旧约束

- 不再要求客户端必须是 Android 或 iOS 原生 App。
- 不再禁止 Web/H5 作为主客户端。
- 不再以课程评审标准作为开发优先级。
- 不再把 Android 编译和真机演示作为默认验证路径。

## 6. 当前推荐下一步

优先创建 Web 前端主应用，而不是继续扩展 Android 客户端。

第一版 Web 客户端目标：

1. 能发送消息并消费 `/api/chat` SSE。
2. 能逐字或分片渲染回答。
3. 能展示 `products` 商品卡片。
4. 能展示 `comparison` 对比卡。
5. 能打开商品详情。
6. 能显示错误态、模型降级提示和后端健康状态。

完成这一步后，这个项目就能从“客户端课题项目”转成“全栈 Agent 项目”的形态。
