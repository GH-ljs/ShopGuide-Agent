# 项目定位：面向秋招简历的 ShopGuide Agent

课程课题已经结束，本仓库后续不再围绕课程评审要求开发。新的目标是把 ShopGuide Agent 打造成适合投递前端、全栈和 Agent 开发岗位的个人项目。

## 新定位

ShopGuide Agent 是一个基于 RAG 的电商智能导购 Agent。核心价值不是套壳聊天，而是把用户自然语言购物需求转成可验证的商品检索、过滤、推荐、对比和决策辅助流程。

```text
uni-app 跨端前端（H5/微信小程序）
-> Node.js 后端 Agent 编排
-> 意图解析、多轮记忆、商品检索、过滤和排序
-> Qdrant + Doubao Embedding 召回
-> DeepSeek 或本地规则生成回答
-> 商品卡、详情页、对比结果和证据链展示
```

Android 客户端作为历史实现保留，但不再是主展示端。用户侧功能统一进入 `app/`。

## 面向岗位的展示重点

### 前端/跨端

- 使用 uni-app + Vue3 + TypeScript 构建一套 H5/微信小程序共用前端。
- 展示复杂业务 UI：聊天流、商品卡、详情页、对比卡、收藏、购物车。
- 处理真实交互状态：loading、错误、重试、空状态、会话历史、本地持久化。
- 通过 API 适配层处理 H5 和小程序差异，避免业务页面分叉。

### 全栈

- 前后端通过清晰 HTTP/SSE API 协作。
- 后端提供健康检查、商品详情、非流式问答、SSE 问答、检索调试和性能统计。
- 本地启动脚本统一拉起 Qdrant、后端和主前端。
- 环境变量和敏感 Key 只放本地 `.env`，不写入仓库文档或源码。

### Agent/RAG

- 突出意图解析、检索、硬过滤、排序、Prompt 构造、模型生成和结构化返回。
- 商品事实必须来自数据集，模型只负责表达和解释。
- 保留 review/debug 证据链，展示“为什么推荐这些商品”。
- 对多轮追问、价格约束、反选条件、商品指代和对比决策补充测试。

## 不再适用的旧约束

- 不再要求客户端必须是 Android 或 iOS 原生 App。
- 不再以课程评审标准作为开发优先级。
- 不再把 Android 编译和真机演示作为默认验证路径。
- 不再维护多套用户前端；用户侧功能统一进入 `app/`。
