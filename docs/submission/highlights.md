# 项目亮点与创新点

建议最终展示控制在 3 点以内，突出“相比普通 RAG 问答方案，本项目更可信、更像导购、更有工程完成度”。

## 亮点 1：可信 RAG，商品事实不由模型编造

普通 RAG 容易把检索结果直接交给模型生成，导致商品、价格、优惠、库存和功效被模型补全。本项目把“理解表达”和“商品决策”拆开：

```text
意图解析/LLM Plan -> 后端 Validator -> 商品硬过滤 -> 向量排序 -> 同批商品生成回答和卡片
```

核心价值：

- LLM 只负责理解需求和组织表达，最终商品集合由后端校验和过滤决定。
- 预算、排除词、序号指代、对比范围等关键约束走确定性逻辑，减少推荐越界。
- 回答文本、商品卡片、详情页和对比卡都绑定同一批 `productId`，避免“说的”和“展示的”不一致。
- 无结果时明确说明商品库没有满足条件的商品，不强行推荐。

## 亮点 2：多轮决策型 Agent，不只是一次性商品搜索

真实导购不是搜一次就结束，而是用户会继续追问、比较、改预算、换品类。本项目围绕多轮对话维护结构化状态：

- 支持“不超过 200”“再便宜点”“第 2 款怎么样”“哪个更清爽”等连续追问。
- 维护 `referenceProducts`、`comparisonProducts` 和 `needs[]`，区分当前候选、最近对比对象和不同购物需求。
- 新品类需求会切换上下文，避免把防晒霜的“清爽/控油/第 2 款”带到笔记本、饮料等后续问题里。
- 对比追问只在用户点名或最近对比过的商品中决策，不重新全库召回导致语义漂移。

## 亮点 3：工程与性能优化，面向真实长对话体验

项目除了推荐链路，也补充了移动端和服务端的性能优化点，体现工程完整度：

- 服务端加入热门问题缓存，对不依赖上下文的高频新搜索复用推荐结果，降低重复检索和生成成本。
- 对话接口采用 SSE 流式返回，用户能先看到回答增量，再接收商品卡片、评审信息等结构化事件。
- Android 客户端使用 Compose `LazyColumn` 实现聊天虚拟列表，只渲染可视区域附近消息，长对话滚动更稳定。
- 商品卡片使用 `LazyRow` 横向虚拟列表，并通过稳定 `key`、`contentType` 和 `productId` 减少流式更新时的无效重组。

评审模式证据链仍可作为演示中的可信性补充，用来展示检索、过滤、排序和商品证据，但不再作为主要创新点。

## 一句话总结

ShopGuide Agent 的亮点是：

```text
可信事实边界 + 多轮导购决策 + 热门缓存/虚拟滚动等工程性能优化
```
