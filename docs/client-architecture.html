入口 · MainActivity.kt
client/app/src/main/java/.../MainActivity.kt
单 Activity 架构，继承 ComponentActivity，通过 setContent {} 挂载 Compose UI 树。 ShopGuideApp() 包裹 MaterialTheme + Surface（背景色 #F6F7F9），根节点为 ChatScreen。 无 Fragment、无 Navigation 组件，MVP 阶段极简设计。
🎨
ChatScreen.kt — 状态管理中心
client/app/src/main/java/.../ui/ChatScreen.kt
整个对话的核心状态全部在此管理：
messages — mutableStateListOf 驱动 LazyColumn 增量更新
isStreaming — 控制输入框禁用和按钮文本切换
isBackendHealthy — 启动时通过 LaunchedEffect + HealthApi 检测
conversationId — UUID 生成，一次会话保持同一 ID

流式更新策略：先 add 空的 Assistant 占位消息，收到 token 回调时用 updateAssistantMessage 做 text 增量拼接；收到 products 回调时替换整组商品卡片。
🎨
Header.kt — 连接状态指示
client/app/src/main/java/.../ui/Header.kt
纯展示组件，接收 isBackendHealthy: Boolean?。
null → "正在检查后端连接"（灰色）
true → "后端已连接"（绿色 #168A45）
false → "后端未连接"（红色 #B42318）
白色背景，标题 "ShopGuide Agent" + 副标题 "RAG 电商智能导购"。

InputBar.kt — 输入交互
client/app/src/main/java/.../ui/InputBar.kt
底栏固定输入区：OutlinedTextField（最多 3 行）+ 发送按钮。
enabled 参数在 isStreaming == true 时置灰，防止并发请求。

MessageBubble.kt — 消息气泡
client/app/src/main/java/.../ui/MessageBubble.kt
根据 message.role 决定布局方向：
User：右对齐，蓝色背景（#2F6FED），白色文字，占宽 78%
Assistant：左对齐，白色背景，深色文字，占宽 92%，下方紧接商品卡片列表
当 message.products 非空时，在气泡下方渲染 ProductCardView 列表。
🎨
ProductCardView.kt — 商品卡片
client/app/src/main/java/.../ui/ProductCardView.kt
Material 3 Card 组件：白色容器、1dp 阴影、8dp 圆角。
展示字段：title（标题加粗）→ brand + price（蓝色 #2F6FED）→ reason（灰色推荐理由）。
当前为纯文本卡片，后续可扩展商品图片和点击跳转详情。
🌐
ChatApi.kt — SSE 流式客户端
client/app/src/main/java/.../network/ChatApi.kt
核心网络层，使用 HttpURLConnection（零第三方依赖）实现 SSE 消费：
1) POST JSON 请求体到 /api/chat
2) BufferedReader 逐行读取 text/event-stream 响应
3) 按 event:/data: 行对解析，分发 4 种回调
4) price 字段做格式化处理（Number→"CNY xxx"）
超时：connect 5s / read 60s。异常和 HTTP 错误统一走 onError。
🌐
ApiConfig.kt + HealthApi.kt
client/app/src/main/java/.../network/
ApiConfig：硬编码 BASE_URL = "http://10.0.2.2:3001"。Android 模拟器通过 10.0.2.2 访问宿主机 localhost。
HealthApi：GET /api/health，超时 3s，返回 Boolean，供 Header 展示连接状态。
📋
Model — 数据类
client/app/src/main/java/.../model/
ChatMessage：id + role + text + products，data class 支持 copy() 做增量更新。
MessageRole：枚举 User/Assistant，避免字符串拼写错误。
ProductCard：title/brand/price/reason，与后端 SSE products 事件字段对齐。

关键交互细节
  • 并发控制：发送按钮在 isStreaming=true 时 disabled，防止用户在流式响应期间发起第二个请求
  • 占位策略：发送用户消息后立即 add 一条 text="" 的 Assistant 消息，token 回调通过 copy(text = old.text + token) 逐步填充
  • 线程模型：ChatApi.streamChat 运行在 Dispatchers.IO，UI 回调通过 scope.launch 切回主线程更新 Compose state
  • 错误兜底：HTTP 非 2xx → onError；网络异常 → onError；后端 SSE error 事件 → onError。三种路径都会在 Assistant 气泡中显示错误文本并恢复 isStreaming
  • session 持久化：conversationId 用 remember { UUID } 持有，Activity 重建时不变，服务重启后后端 session 清空但客户端无感知

📡 SSE 事件解析 & 状态更新机制
ChatApi 事件分发逻辑
// BufferedReader 逐行读取 text/event-stream while (true) { val line = reader.readLine() ?: break when { line.startsWith("event:") → eventName = ... line.startsWith("data:") → handleEvent(eventName, data, ...) } } // handleEvent 分发 "token" → JSONObject(data).optString("content") → onToken "products" → JSONObject(data).optJSONArray("products") → map to List<ProductCard> → onProducts "done" → onDone() "error" → error.message + details → onError
ChatScreen 状态更新
// token: 增量拼接文本 onToken = { token → updateAssistantMessage(messages, id) { old → old.copy(text = old.text + token) } } // products: 整组替换 onProducts = { products → updateAssistantMessage(messages, id) { old → old.copy(products = products) } } // done: 恢复输入 onDone = { isStreaming = false } // error: 显示错误文本 + 恢复输入 onError = { msg → updateAssistantMessage(...) { old.copy(text = "请求失败：$msg") } isStreaming = false }
updateAssistantMessage 辅助函数
  • 通过 messages.indexOfFirst { it.id == messageId } 定位消息
  • 用 messages[index] = transform(old) 触发 Compose 重组
  • ChatMessage 是 data class，copy() 创建新实例 = Compose 能正确 diff 并只重组变化的气泡
  • LazyColumn 使用 key = { it.id } 稳定列表项标识，避免流式更新时列表闪烁

💡 关键设计决策
零第三方网络库
  • 使用系统 HttpURLConnection 而非 OkHttp/Retrofit
  • MVP 阶段减少依赖引入，降低构建复杂度和 APK 体积
  • SSE 协议本身简单（逐行读取），标准库完全够用
  • 代价：手动管理连接生命周期，没有拦截器/重试等高级功能
单 Activity + Compose
  • 不使用 Fragment 或 Navigation 组件，极简架构
  • 所有状态在 ChatScreen 内部用 remember / mutableStateListOf 管理
  • 现阶段仅一个对话页面，无需路由。后续扩展时再引入 ViewModel + Navigation
流式更新的占位-填充模式
  • 发送用户消息后立即创建空 Assistant 消息占位
  • token 回调逐个追加到 text 字段
  • products 回调整组替换 products 字段
  • LazyColumn + key = id 保证占位消息不会因重组而闪烁
模拟器地址硬编码
  • 10.0.2.2 是 Android 模拟器访问宿主机 localhost 的专用地址
  • 硬编码在 ApiConfig 中，后续可改为 BuildConfig 或 SharedPreferences 动态配置
  • 真机调试时需要改为电脑的局域网 IP
Cleartext 明文 HTTP
  • AndroidManifest.xml 中 usesCleartextTraffic="true"
  • 开发阶段后端是 HTTP，不加此配置 Android 9+ 会阻止明文请求
  • 生产发布前需切换为 HTTPS 并移除此配置
商品卡片与文本分离渲染
  • 商品卡片通过独立 SSE products 事件下发，不混在模型生成的文本中
  • 客户端 MessageBubble 将文本和商品列表分开渲染
  • 避免了从自然语言文本中解析商品信息的不可靠方案
📋 前后端接口契约
接口 客户端调用位置 用途 请求方式 响应类型
GET /api/health HealthApi.checkHealth() 启动时检测后端连通性 同步 GET JSON
POST /api/chat ChatApi.streamChat() 核心对话交互 IO 协程 + SSE 流读 text/event-stream
POST /api/conversations/reset （未接入） 新建对话/清空上下文 — JSON
已接入 vs 待接入
  • 已接入：GET /api/health（启动健康检查）、POST /api/chat（SSE 流式对话 + 商品卡片）
  • 待接入：POST /api/conversations/reset（重置会话，客户端重新生成 conversationId 即可等效实现）、GET /api/products（商品列表页，非对话场景使用）
  • 后端保留但客户端暂不需要：POST /api/debug/retrieve（开发调试用）
