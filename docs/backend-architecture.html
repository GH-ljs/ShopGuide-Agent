检索过滤策略（retriever.js 多级漏斗）
  • 第1级 — 类目过滤：根据关键词推断商品大类（美妆护肤/数码电子/服饰运动/食品生活）
  • 第2级 — 商品意图：识别具体商品类型（洁面/耳机/跑鞋/防晒），收紧候选集
  • 第3级 — 价格约束：正则提取预算上限/下限，过滤不符合价格区间的商品
  • 第4级 — 否定排除：提取"不要""不含""除了"等否定词，排除不符合条件的商品
  • 第5级 — 向量相似度排序：在候选集中计算余弦相似度，按得分排序取 Top-K
📦 模块详解
🚀
入口 · index.js
server/src/index.js
后端启动入口。启动时一次性加载商品库到内存，创建向量索引，然后启动 HTTP 服务器监听 3001 端口。 通过依赖注入方式将 config、products、vectorIndex 传入 HTTP handler，方便后续替换框架。
config.js dataLoader.js http.js vectorIndexFactory.js
🌐
HTTP 层 · http.js
server/src/http.js
纯 node:http 实现的路由分发和 SSE 流式输出。5 个 API 端点，支持 CORS。 /api/chat 是核心端点，串联"会话→检索→模型生成→SSE流式返回→商品卡片"完整链路。 所有 SSE 事件（token / products / done / error）通过标准 text/event-stream 格式下发。
memory.js retriever.js llm.js answer.js errors.js
📦
数据加载 · dataLoader.js
server/src/dataLoader.js
递归扫描数据集目录，读取所有 JSON 商品文件。
将原始 JSON 规范化为统一商品结构，关键字段： searchableText 拼接标题、品牌、类目、营销文案、FAQ、评价、SKU 信息，作为检索的核心文本。
同时保留结构化字段（price、skus、imagePath）供商品卡片使用。
node:fs node:path
🔍
检索器 · retriever.js
server/src/retriever.js
RAG 链路核心。实现多级漏斗式商品召回： 类目推断（4大类关键词匹配）→ 商品意图识别 → 价格正则提取 → 否定条件过滤 → 向量相似度排序。
提供 retrieveProductsWithDebug 返回完整调试信息，包括过滤各阶段计数和向量匹配得分。
vectorStore.js qdrantStore.js
🧠
会话记忆 · memory.js
server/src/memory.js
基于内存 Map 的多轮会话管理。每个 conversationId 维护独立的： state（类目、意图、预算、偏好、排除词）和 turns（最近对话记录）。
关键能力："再便宜点"自动降低预算上限、否定词跨轮累积、偏好持续追踪。
检索 query 合并最近用户消息 + 状态文本 + 上轮商品摘要，解决省略式追问。
纯内存 · 零依赖
🔢
向量化 · embedding.js
server/src/embedding.js
双模式文本向量化：
本地模式：基于哈希的伪 embedding（384 维），对分词 token 做哈希投影 + 符号累加 + L2 归一化，零依赖可离线运行。
Ark 模式：调用 Doubao embedding-vision API（1024 维），支持多模态输入（当前仅文本，预留 image_url）。
自动适配多种 API 响应格式（pickEmbedding）。
vectorStore.js Ark API
📐
本地向量索引 · vectorStore.js
server/src/vectorStore.js
纯本地 TF 向量检索。中文用 2-4 字滑窗分词，附带停用词过滤和同义词扩展。对每个商品文档构建 term-frequency 向量，查询时计算余弦相似度排序。
适合开发和离线场景，零外部依赖。
纯本地 · 零依赖
🗄️
Qdrant 向量库 · qdrantStore.js
server/src/qdrantStore.js
封装 Qdrant REST API。提供 Collection 创建（Cosine 距离）、批量向量写入（每批 64 条）、向量相似度检索（带 productId 过滤）。
point id 使用稳定序号，真实商品 ID 存在 payload 中。配合 qdrant.ingest.js 做数据入库，qdrant.health.js 做健康检查。
embedding.js Qdrant REST API
🤖
LLM 调用 · llm.js
server/src/llm.js
OpenAI-compatible 流式聊天接口封装。支持 Doubao/Ark 和 DeepSeek 两种 provider。
异步生成器逐 token yield，SSE 数据用 buffer 累积解析，处理网络切分。
temperature=0.3 保证导购回答稳定可复现。
answer.js Ark / DeepSeek API
💬
回答构造 · answer.js
server/src/answer.js
三块核心功能：
1) buildProductCards — 构造客户端商品卡片（productId、title、price、imagePath、reason）
2) buildLocalAnswer — 无 LLM 时的本地兜底回答模板
3) buildModelMessages — 构造 Prompt（system 约束 + 对话历史 + 用户需求 + 导购状态 + 商品上下文 JSON）
纯逻辑 · 无外部依赖
⚙️
配置 · config.js
server/src/config.js
轻量 .env 解析器（无需 dotenv 依赖）。集中管理所有环境变量：端口、数据集路径、向量库类型、embedding 模式/维度、LLM provider 和 API Key。 支持 embedding 和 LLM 用不同 provider 组合。
node:fs node:path
📋
错误处理 · errors.js
server/src/errors.js
统一 JSON 错误响应和 SSE error 事件的数据结构。5 种错误码：INVALID_JSON、VALIDATION_ERROR、NOT_FOUND、MODEL_ERROR、INTERNAL_ERROR。
SSE error 事件额外携带 details 字段，便于客户端区分检索失败和模型失败。

🔌 API 接口
方法路径说明请求/响应要点
GET /api/health 健康检查 返回 ok、productCount、modelEnabled、llmProvider
GET /api/products 商品列表 返回简化商品列表（productId、title、brand、category、price、imagePath）
POST /api/chat 核心导购对话 请求: { message, conversationId }
响应: text/event-stream — token 流式文本 → products 商品卡片 → done 完成标记
POST /api/conversations/reset 重置会话 请求: { conversationId }，清空该会话的状态和历史，返回新会话快照
POST /api/debug/retrieve 检索调试 请求: { message, conversationId, includeMemory?, limit? }
返回: 解析结果（类目/意图/价格/否定词）、各阶段候选数量、向量匹配得分、最终商品卡片
📡 SSE 事件协议

客户端通过 POST /api/chat 获取 text/event-stream 响应，服务端按顺序发送以下事件：

T
event: token
流式文本片段，客户端逐字/逐词渲染。每段包含 { content: "..." }
P
event: products
结构化商品卡片列表。包含 productId、title、brand、price、imagePath、reason
D
event: done
完成标记 { ok: true, conversationId }。客户端据此结束 loading 状态
E
event: error
错误事件 { error: { code, message, details? } }。客户端据此展示错误提示
设计要点
  • 商品卡片与文本分离：products 事件是商品卡片的唯一可靠来源，客户端不要在模型自然语言文本中解析商品信息。
  • 顺序保证：事件按 token→products→done 顺序发送，后续事件不会早于先前的 token 事件。
  • 错误恢复：chat handler 用 try/catch 包裹整个 RAG 链路，异常时发送 error 事件而非直接断开连接。
  • 本地兜底：未配置 LLM API Key 时，使用 buildLocalAnswer 本地构造回答并模拟流式输出（18ms/片段）。

关键设计决策
  • 零框架依赖（纯 node:http），减少冷启动时间和依赖风险
  • 商品库启动时全量加载到内存（当前 50-100 条规模，最简单稳定）
  • 会话状态存进程内存，服务重启后清空（MVP 阶段合理取舍）
  • vectorIndex.search 接口统一，await 兼容同步/异步实现

{

  title: string,           // 商品标题
  brand: string,           // 品牌
  category: string,        // 大类（美妆护肤/数码电子/...）
  subCategory: string,     // 子类目
  basePrice: number,       // 基础价格
  imagePath: string,       // 主图路径
  skus: [{ properties, price }],  // SKU 规格
  marketingDescription: string,   // 营销文案
  officialFaq: [{ question, answer }], // FAQ
  userReviews: [{ rating, content }],  // 用户评价
  sourceFile: string,      // 数据源文件
  searchableText: string   // 拼接后的检索文本
}
会话状态 (Session)
{
  conversationId: string,
  state: {
    category: string,        // 当前类目
    itemIntent: {            // 商品意图
      itemType, trigger[], terms[]
    },
    maxPrice: number | null, // 预算上限
    minPrice: number | null, // 预算下限
    excludeTerms: string[],  // 排除词（跨轮累积）
    preferences: string[],   // 偏好（清爽/控油/...）
    lastProductIds: string[] // 上轮商品 ID
  },
  turns: [{ role, content, createdAt }],
  lastProducts: Product[]
}
