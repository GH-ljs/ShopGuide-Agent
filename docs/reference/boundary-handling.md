# 边界情况处理说明

本文档整理 ShopGuide Agent 当前对典型边界问题的处理方式。整体原则是：LLM 负责更通用的语义理解和任务规划，后端负责可信校验、兜底纠偏和最终执行，避免错误规划进入检索并展示无关商品卡片。

## 1. 设计原则

当前做法是合理的，但前提不是“完全相信 LLM”，而是：

```text
LLM 先理解用户真实意图
  -> 后端 Validator 校验意图、范围、商品事实和硬约束
  -> LLM 漏判或不可用时，规则 fallback 保证主链路稳定
```

这样比纯规则更通用，也比纯 LLM 更稳。比如“给我点外卖”应由 LLM 理解为外卖服务而不是食品饮料商品；如果 LLM 漏判，后端规则仍会把它拉回 `out_of_scope`。

## 2. 边界类型

| 边界类型 | 触发示例 | 当前处理 | 是否检索商品 | 是否展示卡片 |
| --- | --- | --- | --- | --- |
| 空输入 | 空字符串、只有空格 | HTTP 400，`VALIDATION_ERROR` | 否 | 否 |
| 超长输入 | 粘贴超过 500 字 | HTTP 400，`VALIDATION_ERROR` | 否 | 否 |
| 缺少候选上下文 | 新会话直接问“第二款怎么样” | `missing_context`，提示先给完整需求 | 否 | 否 |
| 明显非商品导购 | “天气怎么样”“帮我写论文” | `out_of_scope`，说明导购边界 | 否 | 否 |
| 服务型请求 | “给我点外卖”“帮我订餐” | `out_of_scope`，不把服务请求当商品搜索 | 否 | 否 |
| 多品类混合 | “想买笔记本和防晒霜” | `multi_need`，提示拆开需求 | 否 | 否 |
| 模型生成失败 | LLM API 异常、权限或网络错误 | 后端退回本地确定性回答，SSE 发 `meta type=fallback` | 是，若检索已成功 | 是 |
| 检索失败 | Qdrant、Embedding、索引异常 | SSE `error`，客户端显示失败并允许重试 | 否 | 否 |
| 客户端连不上后端 | 后端未启动、地址错、网络断开 | 客户端本地归类 `NETWORK_ERROR`，用户消息前显示重试图标 | 否 | 否 |
| 图片加载失败 | 商品图片 404、网络异常、解码失败 | 客户端显示“暂无图片”占位 | 不影响检索 | 商品文字仍展示 |

## 3. 意图边界

边界类意图由 `server/src/services/intent.js` 和 `server/src/services/memory.js` 共同保证。

### `missing_context`

用于处理没有候选商品时的指代或对比问题。

典型输入：

```text
第二款怎么样
2和3哪个好
这款呢
```

如果当前会话没有可参考候选，系统不会从全库乱搜，而是提示用户先提出完整需求。这样可以避免“第二款”被错误理解成某个随机商品。

### `out_of_scope`

用于处理明显超出商品导购范围的问题。

典型输入：

```text
天气怎么样
帮我写论文
给我点外卖
帮我订餐
```

外卖和订餐虽然和“吃”有关，但它们是服务请求，不是当前商品库中的商品导购，所以不能进入食品饮料检索。

### `multi_need`

用于处理一句话里多个商品品类混在一起的情况。

典型输入：

```text
想买笔记本和防晒霜
帮我推荐手机和跑鞋
```

当前客户端一轮只展示一组商品候选卡片。如果强行把多个品类混在一起，会导致回答和卡片难以对齐，所以系统会先提示用户拆开需求。

## 4. LLM 与规则的分工

当前链路不是纯规则，也不是纯 LLM。

有模型 Key 时：

```text
规则先给 fallback hint
  -> LLM 输出结构化 Plan
  -> 后端 Validator 校验
  -> 如果 LLM 漏判边界，规则 fallback 拉回
```

没有模型 Key 或 LLM 解析失败时：

```text
规则解析直接接管
  -> 保证 Demo 和基础 RAG 主链路仍可运行
```

这就是为什么我们仍保留规则：规则不是为了替代 LLM，而是为了做安全护栏、可测回归和无模型兜底。

## 5. 测试覆盖

相关测试主要在：

- `server/src/__tests__/intent.test.js`：验证 LLM Plan、Validator 和边界兜底。
- `server/src/__tests__/memory-eval.test.js`：验证多轮上下文、指代、对比和边界问题。
- `server/src/__tests__/smoke.test.js`：验证 `/api/chat` 端到端行为。

已固化的边界样例包括：

```text
新会话直接问：第二款怎么样
天气怎么样
帮我写论文
给我点外卖
想买笔记本和防晒霜
```
